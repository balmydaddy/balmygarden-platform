## 0. 결론 먼저

셋을 "무료 도구 3개"로 묶으면 판단이 틀어진다. **하는 일이 근본적으로 다르다.**

| 도구 | 무엇을 바꾸나 | 판정 |
|---|---|---|
| Headroom | LLM에 **들어가는 입력**을 줄인다 | **채택** — 로컬 개발 세션 |
| claude-mem | 세션 간 **기억을 자동 주입**한다 | **보류** — 지금 우리 실패 모드와 충돌 |
| OmniRoute | 한도가 차면 **모델 자체를 바꾼다** | **미채택** — 아래 2절 |

가르는 기준은 하나다. **입력을 줄이는 도구인가, 판단 주체를 바꾸는 도구인가.**
앞쪽은 결과가 같고 비용만 준다. 뒤쪽은 결과가 달라지는데 그 사실이 화면에 안 뜬다.

## 1. Headroom — 채택 (로컬 개발 세션)

`headroomlabs-ai/headroom`. 도구 출력·로그·파일·RAG 청크를 LLM에 도달하기 전에 압축한다.
코딩 에이전트 약 20퍼센트, JSON 60~95퍼센트 절감을 표방한다. 라이브러리·프록시·MCP 서버
세 형태로 제공되고 **로컬에서 돌며 데이터가 기기를 벗어나지 않는다**고 명시한다.

**우리에게 맞는 이유가 추측이 아니라 실측이다.** 이 플랫폼 세션에서 GitHub Actions
목록 응답이 **98,386자**로 돌아와 도구 결과 한도를 초과한 일이 오늘만 두 번 있었다.
그때마다 파일로 떨어뜨려 파이썬으로 잘라 읽는 우회를 했다. Headroom이 겨냥하는 게
정확히 그 지점이다.

- 적용 위치: **CEO 로컬 PC의 LOD 개발 세션**. 5시간 롤링 한도를 쓰는 쪽이라 효과가 크다.
- 이 클라우드 세션에는 적용할 수 없다 — 관리형 세션이라 LLM 엔드포인트를 바꿀 수 없다.
- 비용: 없음(COST-01 무관).

**설치 전 알아둘 것 두 가지 (원문 확인 사항).**

1. **`npm`이 아니라 `pip3`다.** 원문이 "여기서 제일 많이 틀려요"로 표시한 항목이다 —
   `npm install headroom-ai`로 깔면 부품만 설치되고 실행 명령이 안 생긴다.
2. **부작용이 하나 있다.** 처음 실행하면 `Serena`라는 코드 탐색 보조 도구가 함께
   설치되고 클로드 설정(`~/.claude.json`)에 등록된다. `headroom unwrap claude`로
   등록까지 정리된다. 설정 파일을 건드리므로 **설치 전 백업을 먼저 뜬다.**
- 터미널 CLI 전용이다 — 데스크톱 앱은 지원하지 않는다(원문 명시).

```bash
# 0. 백업 (파일이 없다는 메시지가 나와도 정상 — 그 줄은 건너뛴다)
cp ~/.claude/settings.json ~/.claude/settings.backup.json
cp ~/.claude.json ~/.claude.backup.json

# 1. 설치 — npm이 아니라 pip3
pip3 install "headroom-ai[all]"

# 2. 확인
headroom doctor

# 3. 압축 모드로 클로드 실행 (쓸 때마다 이 명령으로 켠다)
headroom wrap claude

# 절약량 확인: headroom dashboard   /   해제: headroom unwrap claude
```

## 2. OmniRoute — 미채택

`diegosouzapw/OmniRoute`. 350곳 넘는 제공사를 한 엔드포인트로 묶고, 클로드 한도가 차면
다른 회사 모델로 자동 전환한다. 기술적으로는 잘 만든 도구이고 별점도 높다.
**우리 운영 구조와 충돌하는 지점이 둘 있다.**

### 2-1. AEGIS 게이트 — 최초 판정을 정정한다

**최초에 "한도가 차면 채점자가 조용히 무료 모델로 바뀐다"고 적었다. 그 표현은 틀렸다.**
Notion 원문을 확인한 결과, 가이드가 안내하는 기본 구성은 **환승이 자동이 아니다.**
평소에는 `claude`로 켜고, 한도가 걸린 날에만 `omniroute launch`로 따로 켠다. 원문의
표현 그대로 "평소처럼 `claude`만 치면 OmniRoute를 거치지 않고 원래 클로드 그대로
작동합니다". 즉 **사용자가 매번 명시적으로 고른다.**

자동 전환(폴백 체인)은 원문이 "설정 난이도가 있어 이 가이드에서는 다루지 않습니다"라고
밝힌 **별도 고급 설정**이다. 카드 2장("한도 끝나면 자동 환승")만 보고 자동 전환이
기본값이라고 읽은 것이 내 오독이다.

**정정 후에도 남는 문제는 이것이다.** 환승 모드로 켠 창에서 리뷰를 돌리면, 그 95점을
**어느 모델이 매겼는지가 점수에 안 남는다.** 우리 규칙은 "생성 세션과 분리된 별도
Agent가 95/100"인데, 채점자가 회차마다 달라지면 점수 간 비교가 성립하지 않는다.
자동이냐 수동이냐와 무관하게, 게이트 경로에서는 채점자가 고정돼야 한다.

이건 가정이 아니다. 오늘 리뷰가 실제로 잡아낸 것들이다.

- 적 피해표가 페이즈2 ATK를 빼고 계산돼 위협이 25~35퍼센트 낮게 적힌 것
- `EnemyExecuteSkill` — 코드에 없는 심볼을 문서가 실재처럼 가리킨 것
- 5행짜리 수치표에서 4행이 속성 배율 누락으로 틀린 것

전부 원본 데이터를 다시 계산해야 잡히는 종류다. 채점자가 바뀌면 이 수준이 유지되는지
알 방법이 없고, 그러면 LOD-DEV-03의 자동 루프 전체가 근거를 잃는다.

### 2-2. 사유 저장소가 외부로 나간다 (원문도 같은 경고를 한다)

`lord-of-dark`는 비공개 저장소다. 환승 모드에서는 게임 코드와 설계 문서가 제3자
제공사 서버를 지난다.

**이건 내 추론이 아니라 원문이 먼저 경고하는 항목이다.** Notion 문서의 자물쇠 콜아웃을
그대로 옮긴다.

> 무료 모델로 환승된 순간부터, 내가 보낸 글과 코드는 클로드가 아니라 **해당 무료
> 제공사(제3자)의 서버**로 전송돼요. 회사 코드나 개인정보 같은 민감한 내용은 환승
> 모드에서 다루지 마세요. **무료 목록 중 15곳은 약관 주의 표시가 붙어 있어서**, 쓸지
> 말지 직접 골라 켜게 되어 있습니다.

원문이 스스로 "회사 코드는 환승 모드에서 다루지 마세요"라고 적었다. 우리 저장소는
정확히 그 범주다. `.env.local` 커밋 금지와 같은 계열의 문제다.

### 2-3. 그래서 언제 쓸 수 있나

정정 결과, **"쓰면 안 되는 도구"가 아니라 "쓰면 안 되는 작업이 정해진 도구"다.**
환승이 수동이므로 경계를 사람이 그을 수 있다.

| 작업 | 환승 모드 |
|---|---|
| AEGIS 게이트 리뷰, LOD-DEV-03 사이클 | **금지** — 채점자가 안 고정된다 |
| `lord-of-dark`·`balmydaddy-safety` 등 비공개 저장소 | **금지** — 원문 경고 그대로 |
| 공개 저장소 작업, 검색 요약, 형식 변환 | 가능 |

원문 FAQ도 같은 선을 긋는다 — "중요한 작업은 클로드 한도 안에서, 반복 작업은 환승
모델로 나누는 걸 추천해요." 우리 백로그는 지금 대부분 앞쪽(비공개 저장소 + 게이트)이라
도입 이득이 작다는 결론은 유지된다.

### 2-4. Headroom과 동시 사용 금지 (원문 지적)

원문이 명시한다 — 둘은 **클로드 앞단의 같은 자리**를 차지하므로 같이 쓰지 말고 하나만
고르라고 한다. OmniRoute에는 압축 기능(RTK+Caveman)이 내장돼 있어서, 환승이 목적이면
OmniRoute 하나, 압축만 원하면 Headroom 하나다. **우리는 압축만 필요하므로 Headroom
하나가 맞다.**

## 3. claude-mem — 보류

`thedotmack/claude-mem`. 세션 내용을 요약해 저장하고 다음 세션에 자동으로 주입한다.

기능 자체는 문제가 없다. **시점이 문제다.** 이번 주 우리가 반복해서 겪은 실패는 전부
같은 종류였다 — 오래된 서술이 사실인 것처럼 남아 있고, 그걸 근거로 다음 판단이 틀어졌다.

- `docs/battle-system.md` 부록이 "해소 확인"인데 본문은 "몬스터는 기본 공격만 한다"였다
- 행 번호 인용 6개가 커밋 두 건 사이에 전부 어긋났다
- GDD 속성 상성표가 코드와 네 곳 달랐다

여기에 **내가 감사할 수 없는 자동 주입 기억층**을 얹으면 같은 실패가 한 겹 더 생긴다.
게다가 LOD-DEV-03 루프는 매 사이클 "그 시점의 실제 백로그"를 다시 읽도록 일부러 설계돼
있다 — 기억이 아니라 현재 상태에서 출발하라는 뜻이다. 그 설계와 정면으로 어긋난다.

원문에서 추가로 확인한 사실 하나 — **기억은 내 컴퓨터에 저장된다.** 즉 2-2의 외부
유출 문제는 claude-mem에는 해당하지 않는다. 보류 사유는 유출이 아니라 위의 감사
불가능성 하나다.

**재검토 조건**: 문서와 코드의 불일치를 자동으로 잡는 장치가 먼저 자리를 잡은 뒤.
그때는 기억층이 위험이 아니라 도움이 된다.

```bash
# 참고 — 채택 시 설치 명령 (지금은 실행하지 않는다)
npx claude-mem install
# 설치 후 클로드 코드를 완전히 껐다 켜야 작동한다
```

## 4. 일반 기준 (다음에 비슷한 게 왔을 때)

1. **모델을 바꾸는 도구와 입력을 줄이는 도구를 구분한다.** 후자는 결과가 같고 비용만
   준다. 전자는 결과가 달라지는데 그 사실이 안 보인다.
2. **품질 게이트가 걸린 경로에는 모델 대체를 넣지 않는다.** 점수의 의미가 사라진다.
3. **사유 저장소가 실리는 경로에 제3자 제공사를 기본값으로 두지 않는다.**
4. **자동 주입은 감사 가능할 때만.** 무엇이 왜 주입됐는지 확인할 수 없으면 오류가
   조용히 번진다.
5. 무료라는 사실은 채택 사유가 아니다. COST-01은 비용을 막는 기준이지 도입을 권하는
   기준이 아니다.

## 6. 2차 적용 — Graphify (CEO 지시 2026-09-03)

**판정: 조건부 채택. 탐색용으로만 쓰고 AEGIS 리뷰 게이트 경로에는 넣지 않는다.**

CEO가 공유한 가이드는 "AI 사용량 70배 절감"을 표방한다. 폴더를 한 번 읽어 코드 지도
(`graph.json`)를 만들고, 이후 AI가 파일을 여는 대신 그 지도를 보게 하는 도구다.
이 세션에서 실제로 설치(`pip install graphifyy`, v0.9.53)해 플랫폼 저장소에 돌렸다.

### 무엇을 바꾸는 도구인가 (TOOL-01 1차 분류)

**입력을 줄이는 도구다.** Headroom과 같은 계열이고 OmniRoute와 다르다 — 모델을
바꾸지 않으므로 채점자가 흔들리지 않는다. 이 축에서는 통과다.

### COST-01 점검 — 통과, 단 조건이 있다

패키지를 직접 뒤져 확인했다.

| 대상 | 처리 | 비용 |
|---|---|---|
| 코드 파일 | 로컬 AST 파싱 | LLM 호출 0회, 0원 |
| 문서·PDF·이미지 | `GEMINI_API_KEY`가 **이미 설정돼 있을 때만** Gemini | 키 없으면 호스트 세션이 대신 |
| `ANTHROPIC_API_KEY`·`OPENAI_API_KEY` | **아예 읽지 않는다** | 해당 없음 |

**조건: `GEMINI_API_KEY`·`GOOGLE_API_KEY`를 설정하지 않는다.** 설정하는 순간 유료
경로가 기본값이 된다 — COST-01이 정확히 막는 형태다. 키가 없으면 문서 추출이
Claude Pro 세션 몫으로 돌아오므로 추가 비용이 0이다.

### 실측 — 표방 71.5배, 우리 저장소 3.0배

`graphify update .`을 플랫폼 저장소에 돌려 노드 934·엣지 1018·커뮤니티 69를 얻었다
(LLM 호출 0회). 같은 질문을 두 방식으로 답할 때의 크기를 쟀다.

| 방식 | 크기 |
|---|---|
| 관련 파일 3개를 직접 읽기(`cron/route.ts`+`blogger.ts`+`internalAuth.ts`) | 52,864 bytes |
| `graphify query "cron route handler" --budget 2000` | 17,594 bytes |
| **절감** | **3.0배** |

71.5배는 만든 쪽의 자체 실험값이고 제3자 검증이 아니다(가이드도 그렇게 밝힌다).
우리 값은 3.0배다. 유의미하지만 한 자릿수다.

### 우리 저장소에서 드러난 한계

**질문의 모양에 따라 결과가 갈린다.** 코드형 질문("cron route handler")은 잘 먹는다 —
`cron/route.ts` → `GET()` L177 → `blogger.ts` → `publishToBlogger()` L117까지 호출
관계로 짚어준다. 반면 자연어 도메인 질문("cron이 블로그 초안을 만드는 경로는
어디인가")은 `CLAUDE.md`·`docs/`의 마크다운 제목만 52개 돌려주고 정작 코드 경로를
못 짚었다. 우리 플랫폼 저장소는 문서가 30편이라 제목 노드가 그래프를 덮는다.

### AEGIS 게이트에 넣지 않는 이유 (TOOL-01 1번의 확장)

TOOL-01 1번은 "품질 게이트가 걸린 경로에 **모델 대체**를 넣지 않는다"였다. Graphify는
모델을 바꾸지 않지만 **근거를 바꾼다.** 리뷰 에이전트가 소스 대신 지도를 읽고 답하면,
그 판정의 근거가 원본이 아니라 요약본이 된다. 지도는 `update`를 안 돌리면 낡는다.

이 세션의 이력이 그 위험을 그대로 보여준다 — 2026-09-01~03의 분리 리뷰 5회가
전부 "커밋 메시지의 주장을 코드로 대조"해서 결함을 찾아냈다(가동률표 오류, 존재하지
않는 심볼, 재현 불가한 밸런스 수치). 요약본을 봤으면 못 찾았을 것들이다.

**그래서 `graphify claude install`(자동 주입)을 켜지 않는다.** 필요할 때
`graphify query`를 명시적으로 부르는 방식만 쓴다. 이건 claude-mem을 보류한 것과
같은 이유의 절반이다 — 나머지 절반(감사 불가)은 Graphify에 해당하지 않는다.
`graph.json`·`GRAPH_REPORT.md`·`graph.html`이 저장소 안의 파일이라 무엇이 들어 있는지
언제든 열어볼 수 있다. 그 점에서 claude-mem보다 낫다.

### 운영 규칙

1. **탐색에만 쓴다.** "이게 어디 있나", "무엇이 무엇을 부르나"에 쓰고, 판단·리뷰의
   근거로는 원본 파일을 읽는다.
2. **`GEMINI_API_KEY`를 설정하지 않는다.** COST-01.
3. **자동 주입(`graphify claude install`)을 켜지 않는다.** 명시 호출만.
4. **`graphify-out/`은 커밋하지 않는다.** 2.1MB 생성물이고 `graphify update`로 언제든
   다시 만든다. `.gitignore`에 넣었다.
5. **지도가 낡으면 답이 틀린다.** 코드를 고친 뒤 `graphify update .`을 돌리지 않으면
   없는 심볼을 가리킨다. 명시 호출 방식이라 낡은 줄 모르고 쓰는 사고는 안 나지만,
   쓰기 전에 갱신하는 습관이 필요하다.

### 미확인

| 항목 | 상태 |
|---|---|
| `lord-of-dark`에서의 절감률 | 미측정. 코드 80편·문서 26편이라 플랫폼보다 코드 비중이 높아 더 나을 수 있다 |

| 71.5배 재현 | 안 했다. 만든 쪽이 실험 폴더를 공개했다지만 대조하지 않았다 |

## 7. 3차 적용 — Agent-Reach (CEO 지시 2026-09-06)

CEO가 인스타그램 릴스 영상을 주고 "적용해봐"라고 지시했다. 릴스는 이 세션 프록시에서
차단돼 URL로는 못 읽었고, CEO가 올려준 영상 파일(39.2초)을 프레임으로 뜯어 전량 판독했다.

### 무엇인가

`Panniantong/Agent-Reach`. MIT, Python 3.10+, GitHub 별 **78.3k**(2026-09-06 조회 실측 —
영상 속 77,166과 다르다. 영상 제작 시점 값으로 보인다). AI 에이전트가 15개 플랫폼의
실시간 콘텐츠를 읽게 해주는 CLI다 — 웹 본문, 유튜브 **자막 전체**, 레딧·V2EX 스레드와
댓글, 인스타·깃허브 프로필.

판매 문구의 핵심이 **"공식 창구를 안 지난다"**다. 공식 API를 우회하므로 구독료도 API 키도
안 든다.

### 판정 — 조건부, 그리고 이 세션에는 적용하지 않는다

| 사용처 | 판정 | 사유 |
|---|---|---|
| 이 클라우드 세션 | **적용 안 함** | 실익이 0이다(아래 실측) |
| 쿠키·로그인이 필요한 채널 | **사용 금지** | 저장소와 설치 문서 **양쪽이 계정 정지 위험을 스스로 경고한다** |
| 자동 설치(한 줄 붙여넣기) | **켜지 않음** | TOOL-01 3번(감사 가능할 때만)과 정면 충돌 |
| CEO 로컬 PC, 쿠키 불필요 채널만 | **CEO 판단 사항** | 실익은 있다. ToS 리스크는 0이 아니다 |

### 1. 이 세션에서는 깔아도 못 쓴다 (실측)

이 원격 세션은 egress 프록시가 도메인 단위로 막는다. 대상 도메인에 직접 붙어 봤다.

| 도메인 | 결과 |
|---|---|
| `www.instagram.com` | 연결 실패(차단) |
| `www.youtube.com` | 연결 실패(차단) |
| `www.reddit.com` | 연결 실패(차단) |
| `x.com` | 연결 실패(차단) |
| `raw.githubusercontent.com` | 301 (통과) |

**도구를 바꿔도 프록시는 그대로다.** Agent-Reach를 깔아도 그 요청 역시 같은 프록시를
지나므로 인스타·유튜브·레딧·X는 여전히 못 읽는다. CEO가 준 릴스 링크를 읽으려던 목적에
이 환경에서는 효과가 없다.

### 2. 계정 정지 위험 — 저장소가 스스로 경고한다

README에 `封号风险提醒`(계정 정지 위험 안내)이 있다. 쿠키 로그인을 쓰는 플랫폼
(트위터·샤오홍슈·레딧·페이스북·인스타그램)에서 플랫폼에 탐지돼 정지될 수 있다는 것이다.
설치 문서는 한 발 더 나아가 **"본계정 말고 부계정을 쓰라, 쿠키 인증은 계정 정지와 자격증명
노출 위험이 있다"**고 적는다.

우리에게 이건 추상적 위험이 아니다. **Threads·인스타그램은 안전관리 상품 홍보 채널이고
그 계정은 CEO 개인 계정이다.** 제재당하면 판매 유입 경로가 사라진다.

같은 판단을 이미 한 적이 있다 — 네이버 블로그 자동 발행(2026-08-22). "기술적으로 가능하지만
저품질 판정이 글이 아니라 **계정 단위**로 걸려서, 얻는 것 대비 잃는 것이 비대칭으로 크다"고
정리했다. 논리가 그대로 적용된다.

### 3. 설치 방식이 TOOL-01 3번과 충돌한다

홍보 문구는 "한 줄 붙여넣으면 에이전트가 알아서 깐다"다. 실제로 그 한 줄은 원격
`docs/install.md`를 에이전트가 읽고 그 안의 명령을 실행하게 하는 것이다. 실행되는 것은
`pipx install https://github.com/Panniantong/agent-reach/archive/main.zip`과
`agent-reach install --env=auto --system`이다.

둘이 걸린다.
1. **감사가 어렵다.** 무엇이 왜 설치됐는지 사람이 확인하기 전에 실행된다. TOOL-01 3번이
   claude-mem을 보류한 것과 같은 이유다.
2. **`main.zip`은 고정 버전이 아니다.** main 브랜치가 바뀌면 다음 설치가 다른 것을 깐다.
   핀 없는 의존성이다.

쓸 거라면 install.md를 사람이 읽고 명령을 직접 친다. 그건 "한 줄"의 편의를 포기하는 것이고,
그 편의가 이 도구의 주 판매점이라는 점은 기록해 둔다.

### 4. COST-01은 통과한다 — 그게 채택 사유는 아니다

MIT에 API 키가 필요 없어 과금 경로가 없다. 다만 TOOL-01이 이미 못 박은 대로 **무료라는
사실은 도입 사유가 아니다.** 비용을 막는 기준이지 도입을 권하는 기준이 아니다.

### CEO 판단이 필요한 것 하나

**로컬 PC에서 쿠키 불필요 6종(Web·YouTube·RSS·검색·GitHub)만 쓸 것인가.**

- 실익: 유튜브 자막 전체 확보 — 지금은 영상 자료를 프레임으로 뜯어 읽고 있다(이번 건이
  그 사례다). 자막을 바로 받으면 그 수고가 없어진다.
- 위험: 로그인을 안 하므로 **계정 정지 위험은 없다.** 다만 공식 API 우회라 각 플랫폼
  ToS 리스크가 0은 아니다.
- 조건(붙인다면): 쿠키 채널 설치 금지(`--channels`에 로그인 계열을 넣지 않는다),
  자동 설치 금지(사람이 명령 실행), AEGIS 리뷰 게이트의 근거로 쓰지 않는다(Graphify와 같은 이유 —
  근거가 원본에서 도구 출력으로 바뀐다).

### 미확인

| 항목 | 상태 |
|---|---|
| 실제 설치·동작 | 안 했다. 이 세션은 대상 도메인이 막혀 검증 자체가 안 된다 |
| 코드 감사 | README와 install.md만 읽었다. 패키지 내부는 안 봤다 |
| 별 78.3k의 성격 | 조회 실측이지만 별 수는 품질 지표가 아니다 |
| 각 플랫폼 ToS 위반 여부 | 법률 판단이라 하지 않았다. "우회"라고 저장소가 스스로 적은 것만 사실로 다룬다 |

### 채택한 것 — 샷 구조는 공짜고 도구와 무관하다

한 편을 통으로 만들지 말고 4샷으로 나누는 구성이다. 도구를 안 깔아도 쓴다.

| 샷 | 목적 | 규칙 |
|---|---|---|
| 1 훅 | 처음 1초에 보여줄 문제나 결과 | 얼굴·제품·강한 움직임 중 **하나만** |
| 2 전개 | 무엇을 어떻게 쓰는지 | 화면·손·결과 중 **하나에 집중** |
| 3 변화 | 전과 후가 보이는 장면 | 비교가 화면에 있어야 한다 |
| 4 마무리 | 다음 행동 **하나만** | 저장·댓글·링크 중 하나 |

공통 규칙 둘: **샷별 목적을 한 줄씩 먼저 쓰고** 생성에 들어간다. 같은 주인공·
같은 분위기·같은 비율을 유지하도록 프롬프트에 반복해서 넣는다.

이건 STROBE(MV·비주얼)와 마케팅 콘텐츠에 쓸 수 있다. BLOG-01의 "시각 요소 없이
400자 넘기지 않기"와 같은 성격의 배치 기준이고, 비용이 0이다.

## 10. 6차 적용 — Agency Agents 재공유 (CEO 지시 2026-09-14)

**판정 유지: 저장소·앱 미설치.** §8의 4차 적용(2026-09-12)과 같은 도구다.
이번 공유는 설치 경로(네이티브 앱·스크립트·수동 복사)와 7명 선별안이
추가됐다. 저장소는 실재한다 — `msitarzewski/agency-agents`, 스타 152k, MIT.
**README 표기는 "230+"이고 공유글의 264와 다르다** — 숫자는 README를 따랐다.

### 오케스트레이터 패턴을 안 받는 이유

이번 공유의 핵심은 "비서실장 한 명에게만 말한다"는 구조다. 우리에겐 그
자리가 이미 CONDUCTOR다. 층을 하나 더 넣으면 두 가지가 깨진다.

1. **블랙박스 배정 금지와 충돌한다.** CLAUDE.md는 에이전트 배정 이유를
   항상 공개하라고 정해 뒀다. 라우팅이 서브에이전트 안에서 일어나면
   누구를 왜 불렀는지가 CEO에게 안 올라온다.
2. **CEO → CONDUCTOR → 오케스트레이터 → 작업자**로 층이 늘어난다.
   층마다 맥락이 깎이는데, 얻는 건 이미 있는 기능이다.

### 7명 중 우리 자리에 이미 있는 것

| 제안된 역할 | 우리 대응 |
|---|---|
| Frontend Developer / UI Designer | ZERO(A-03) |
| Ad Creative Strategist | NOVA(A-06) + SELL-01. **별도 에이전트가 광고 문구를 뽑으면 AEGIS 표시광고 게이트를 우회할 위험이 있다** |
| Reality Checker | CLAUDE.md 증거 기반 보고 + 미확인 명시 |
| Reddit Community Builder | 해당 채널을 안 쓴다. egress가 막고, 계정 단위 제재 비대칭은 Agent-Reach 판정(§7)과 같은 계열 |

### 실제로 걸린 것 하나 — 코드 보안 감사

`AI-Generated Code Security Auditor`만 우리에게 빈자리였다. CLAUDE.md에
`.env.local` 커밋 금지는 있는데 **확인하는 절차가 없었다.** 이번 주에만
`IG_ACCESS_TOKEN`·`UNITY_LICENSE`·`GEMINI_API_KEY` 세 종류의 시크릿을 다루는
코드를 건드렸고 외부 노출 경로가 늘고 있다.

**페르소나가 아니라 훅으로 받았다** — `.claude/hooks/check_secrets.py`.
§8에서 정한 기준("정의 파일은 매 사이클 반복 타이핑하던 걸 뺄 때만 만든다")에
비추면 세 번째 에이전트 파일을 만들 근거가 아직 없다. 반면 훅은 LLM 호출 0회,
비용 0, 무엇을 왜 잡았는지가 정규식에 남아 감사가 된다.

검사 다섯 가지 — 알려진 토큰 접두사 / 개인키 블록 / Bearer 뒤 긴 리터럴 /
시크릿 이름에 긴 문자열 직접 대입 / 시크릿 환경변수를 로그로 흘림.
**길이·불리언 같은 파생 정보만 찍는 형태는 의도된 진단이라 제외**했다 —
`unity-ci.yml`의 라이선스 형태 점검이 그 예다.

실측: 합성 양성 4종 4건 전부 탐지, 우리 실제 파일 5종에서 오탐 0건.

**한계**: 문자열 모양만 본다. 값이 살아 있는 키인지 모르고, 짧거나 평범하게
생긴 시크릿은 못 잡는다. 훅이 조용한 게 안전하다는 뜻이 아니다.
