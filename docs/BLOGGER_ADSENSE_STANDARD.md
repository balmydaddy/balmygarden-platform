# Blogger 애드센스 기준 (ADSENSE-01)

> 수립: 2026-08-26, CEO 지시 ("애드센스 하려고 하는데 기준 미달이라 필요하다")
> 대상: `balmydaddy.blogspot.com` (`src/lib/blogger.ts` → `publishToBlogger`)
> 관련 기준: `docs/BLOG_CONTENT_STANDARD.md`(BLOG-01), CLAUDE.md의 MULTI-01·SELL-01·COST-01

---

## 0. 결론 먼저

**지금 미달인 이유는 글이 짧아서가 아니다. 글을 만드는 방식과 사이트 구조 때문이다.**

현재 Blogger 파이프라인은 트렌드 조사 → INK 집필 → CHECK 검토 → CHIEF 검토 → AEGIS
게이트 → 자동 발행인데, **이 다섯 단계가 전부 LLM이다.** 사람이 직접 겪은 일, 직접 찍은
사진, 직접 측정한 수치가 한 줄도 안 들어간다. 이미지조차 `이미지프롬프트`로 AI가 만든다.

구글은 2024년 3월 스팸 정책 개정에서 대규모 콘텐츠 남용(scaled content abuse)을
**"자동화·사람·혼합 방식과 무관하게 적용"**한다고 명시했다(CLAUDE.md MULTI-01에 이미
인용돼 있는 근거다). 매일 기계가 쓴 글이 쌓이는 사이트는 개별 글의 완성도와 무관하게
이 항목에 걸린다. 심사자가 보는 건 글 한 편이 아니라 **사이트 전체의 성격**이다.

그래서 이 문서는 두 층으로 나뉜다. **사이트 레벨(1~2절)이 승인의 실질 관문이고,
글 레벨(3절)은 그 다음이다.** 순서를 바꾸면 글을 아무리 늘려도 계속 떨어진다.

## 1. 확인 범위 — 무엇이 원문이고 무엇이 미확인인가

정직하게 구분해 둔다. 이 문서를 나중에 읽을 때 근거의 등급을 알아야 한다.

| 구분 | 내용 |
|---|---|
| **원문 확인됨** | CEO가 직접 붙여넣은 정책 발췌 2건(아래 1-1) |
| **원문 대조 실패** | 참조 URL 전부 — `support.google.com` / `developers.google.com` / `adsense.googleblog.com`이 이 세션의 네트워크 프록시에서 차단됐다(실측). 인용하지 않았다. |
| **미확인** | 현재 블로그의 실제 상태 — `balmydaddy.blogspot.com`도 차단돼 게시글 수·고정 페이지 유무·메뉴 구성을 확인하지 못했다. **2절 체크리스트는 CEO가 직접 눈으로 확인해야 한다.** |
| **미확인** | 애드센스 승인에 필요한 최소 글 개수·분량. **구글은 이 수치를 공개하지 않는다.** "글 30개 이상" 같은 항목은 전부 출처 불명의 통설이라 이 문서에 넣지 않았다. |

### 1-1. 원문 (CEO 제공)

> **가치가 별로 없는 콘텐츠**
> 사용자에게 유용하지 않으며 이해하기 어려운 콘텐츠(예: 필러 텍스트 또는
> 'ipsum lorem 텍스트')입니다.

> **게시자 콘텐츠가 없는 화면에 Google 게재 광고**
> 다음과 같은 화면에는 Google 게재 광고가 허용되지 않습니다.
> * 게시자 콘텐츠가 없거나 가치가 별로 없는 콘텐츠를 사용한 화면
> * 아직 미완성 상태인 화면
> * 알림, 탐색 또는 기타 행동 목적으로 사용되는 화면

두 번째 항목은 글 내용이 아니라 **광고가 붙는 화면**에 대한 규정이다. Blogger에서
이게 걸리는 자리가 실제로 있다(2-3절). LOD 게임 앱에 광고를 붙일 때도 같은 조항이 적용된다.

### 1-2. 참조 URL (원문 대조 미실시)

CEO 제공 목록. 프록시 차단으로 이 세션에서는 열지 못했다. **CEO가 직접 열어 이 문서와
대조해야 하고, 충돌하면 원문이 우선한다.**

- `support.google.com/adsense/answer/10502938` (최소 콘텐츠 요건)
- `support.google.com/adsense/answer/10015918`
- `support.google.com/adsense/answer/48182`
- `support.google.com/publisherpolicies/answer/11035931`
- `support.google.com/publisherpolicies/table/10563033#low-value-content`
- `support.google.com/admob/answer/6128543`
- `support.google.com/webmasters/answer/9044175` (빈약한 콘텐츠)
- `developers.google.com/search/docs/essentials`
- `adsense.googleblog.com` 2012-04 / 2012-09 고품질 사이트 팁

## 2. 사이트 레벨 — 승인의 실질 관문

**이 절이 안 끝나면 3절은 의미가 없다.**

### 2-1. 자동 발행을 켜지 않는다 (최우선)

승인 심사 중에도, 승인 후에도 **기계가 매일 자동으로 글을 올리는 구조로 돌아가지 않는다.**

지금 `CRON_LLM_ENABLED`가 기본 false라 Blogger 발행은 이미 멈춰 있다(COST-01 조치의
부수 효과). 이 상태를 **의도적으로 유지한다.** 유료 API 잔액이 생겨도 이 스위치는 켜지
않는다 — 비용 문제가 아니라 애드센스 문제다.

Blogger 글은 네이버 초안과 같은 방식으로 **CONDUCTOR 세션이 직접 쓴다.** 추가 비용이 0이고
(Claude Pro), 발행 전에 CEO가 한 번 본다. 기계가 쓰는 건 같지만 **양산 파이프라인이 아니라
건별 작업**이라는 점이 다르고, 그 차이가 발행 빈도와 1차 자료 비중으로 드러난다.

### 2-2. 고정 페이지 3종 — 없으면 만든다

**CEO 확인 필요 항목.** 애드센스 심사는 글 말고 이것부터 본다.

| 페이지 | 들어가야 하는 것 |
|---|---|
| 소개 (About) | 누가 쓰는 블로그인가. 안전보건 실무 4년차·산업안전기사·제조업 안전보건팀이라는 **검증 가능한 범위**만. 과장 금지(표시광고법·SELL-01). |
| 연락처 | 실제로 연락이 닿는 수단 1개 이상. 이메일이면 충분하다. |
| 개인정보처리방침 | 광고 게재 시 쿠키·식별자 수집이 발생한다는 고지. 애드센스는 이 페이지를 사실상 요구한다. |

세 페이지 전부 **메뉴나 사이드바에서 클릭 한 번으로 닿아야 한다.** 글 밑에 링크만
박아두면 심사자가 못 찾는다.

### 2-3. "게시자 콘텐츠가 없는 화면"에 광고가 붙지 않게 한다

1-1의 두 번째 원문이 걸리는 자리다. Blogger에서 실제 위험 지점:

- **라벨/태그 아카이브 페이지** — 글 목록만 있고 본문이 없다
- **검색 결과 페이지** — 결과가 0건이면 빈 화면에 광고만 남는다
- **비어 있거나 초안 상태인 페이지**

조치: 광고 코드를 넣을 때 **글 본문 페이지에만** 뜨도록 하고, 아카이브·검색 결과에는
게재하지 않는다. Blogger 테마에서 조건부로 처리한다.

### 2-4. 주제를 좁힌다

현재 콘텐츠 축이 안전관리·음악·게임개발·자동매매·부업으로 다섯 갈래다. 사람이 운영하는
블로그로는 자연스러울 수 있지만, **심사에서는 "이 사이트가 무엇에 대한 사이트인가"에
답이 안 나오는 상태**로 보인다.

권고: **안전보건 실무를 주축**으로 삼는다. CEO의 실제 경력이 근거로 붙는 유일한 축이고,
크몽 상품과도 이어진다. 나머지 축은 라벨로 분리하되 발행 비중을 낮춘다.

### 2-5. 채널 중복을 만들지 않는다 (MULTI-01 재확인)

네이버 초안과 Blogger 글에 **같은 원고를 올리지 않는다.** 이미 CLAUDE.md MULTI-01이
금지하고 있는데, 애드센스 관점에서는 더 직접적인 탈락 사유가 된다 — 다른 곳에 이미 있는
글이면 "게시자 콘텐츠"로서의 가치가 없다.

같은 소재를 다룰 때도 제목·구조·분량·톤을 새로 쓰고, 이미지도 다시 만든다.

## 3. 글 레벨 — 한 편이 갖춰야 할 것

`docs/BLOG_CONTENT_STANDARD.md`(BLOG-01)가 **배치**를 정한다. 이 절은 그 위에 얹는
**내용의 실질** 기준이다. 둘 다 통과해야 한다.

### 3-1. 1차 자료가 최소 하나 들어간다 (필수)

가장 중요한 항목이다. "다른 데서도 읽을 수 있는 내용"만으로 채워진 글은 분량과 무관하게
가치가 별로 없는 콘텐츠다. 아래 중 **최소 하나**가 글 안에 있어야 한다.

| 유형 | 예 |
|---|---|
| 직접 찍은 사진 | 현장 사진, 서식 화면, 장비 상태 (사업장명·상표·개인정보 노출 금지) |
| 직접 측정한 수치 | 판매 건수, 커밋 수, 처리 시간, 시트 개수 — **실제 값만** |
| 직접 만든 도표·서식 | 체크리스트, 비교표, 절차도 |
| 실제 겪은 판단 과정 | 무엇을 왜 그렇게 정했는지. **지어낸 일화는 절대 금지** |

없으면 발행하지 않는다. 채워 넣지 말고 비운 채로 보류한다.

### 3-2. 필러를 넣지 않는다

원문이 "가치가 별로 없는 콘텐츠"의 예로 든 게 필러 텍스트다. 실무에서 필러는
lorem ipsum 형태로 오지 않고 아래 형태로 온다.

- 서론에서 주제를 다시 설명하는 문단
- "~에 대해 알아보겠습니다" 류의 예고 문장
- 본문 내용을 되풀이하는 결론 문단
- 검색어를 끼워 넣으려고 만든 문장
- 분량 채우려고 넣은 일반론

**분량 기준을 채우려고 이런 걸 넣는 순간 기준을 어긴 것이다.** 분량이 모자라면 소재를
더 파거나 글을 나눈다.

### 3-3. 이미지는 근거여야 한다

BLOG-01이 이미 정한 원칙이다. 애드센스 관점에서 하나 더 붙는다.

**AI 생성 이미지로만 채우지 않는다.** 글도 기계가 쓰고 이미지도 기계가 만들면 사이트
전체가 자동 생성물로 읽힌다. 직접 찍은 사진이나 직접 만든 도표를 **글마다 최소 1장**
넣는다. AI 이미지는 그 외 자리를 보조하는 용도로만 쓴다.

### 3-4. 발행 전 자체 점검

| 항목 | 기준 |
|---|---|
| 1차 자료 | 최소 1개 (3-1) |
| 직접 만든 시각 요소 | 최소 1장 (3-3) |
| 시각 요소 없이 이어지는 텍스트 | 400자 이하 (BLOG-01) |
| 필러 문단 | 0개 (3-2) |
| 다른 채널과 동일·유사 | 0건 (2-5, MULTI-01) |
| 검증 불가한 주장 | 0건 — 확인 못 한 건 "미확인"으로 쓴다 |
| 최상급·단정 표현 | 0건 (표시광고법, SELL-01) |
| 지어낸 일화 | 0건 |

## 4. 발행 파이프라인에 적용하는 법

`src/app/api/cron/route.ts`의 blogTeam·musicBlog 경로에 그대로 얹는다.

- **AEGIS 게이트에 3-4 체크리스트를 명시적으로 넣는다.** 지금 AEGIS 프롬프트는 "애드센스
  정책"을 뭉뚱그려 언급할 뿐이라 무엇을 보라는 건지가 없다. 항목을 나열해야 판정이 된다.
- **1차 자료 항목은 LLM이 자체 판정할 수 없다.** 사진을 찍었는지 수치를 실제로 쟀는지는
  코드가 모른다. 그래서 이 항목은 **자동 통과시키지 않고 CEO 확인 대기로 빼는 게 맞다** —
  자동 발행을 안 하기로 한 2-1의 실질적 이유가 이것이다.
- `publishToBlogger` 호출 조건에 위 게이트를 통과한 경우만 남긴다.

## 5. 승인 신청 전 체크리스트 (CEO 실행)

이 순서대로 한다. 위에서부터 막히면 아래는 의미가 없다.

1. 블로그에 **소개·연락처·개인정보처리방침** 페이지가 있는지 확인하고 없으면 만든다 (2-2)
2. 메뉴에서 세 페이지에 **클릭 한 번**으로 닿는지 확인한다
3. 기존 게시글을 훑어 **1차 자료가 하나도 없는 글**을 골라낸다 — 보강하거나 비공개로 내린다 (3-1)
4. 아카이브·검색 결과 페이지에 광고가 안 붙게 테마를 확인한다 (2-3)
5. 주축 주제를 정하고 라벨을 정리한다 (2-4)
6. 네이버에 올린 글과 **같은 원고가 Blogger에 있는지** 확인한다 (2-5)
7. 그 다음에 신청한다

## 6. CEO 결정·확인이 필요한 것

| 항목 | 왜 |
|---|---|
| 현재 블로그 상태 전반 | `balmydaddy.blogspot.com`이 이 세션 프록시에서 차단돼 **게시글 수·고정 페이지 유무·메뉴 구성 전부 미확인**이다 |
| 주축 주제 (2-4) | 안전보건으로 좁히는 게 권고안이나, 최종 판단은 CEO 몫이다 |
| 참조 URL 원문 대조 (1-2) | 이 세션에서 못 열었다. 이 문서와 충돌하면 원문이 우선한다 |
| 자체 도메인 사용 여부 | `blogspot.com` 서브도메인도 정책상 문제는 없으나, 도메인 구입은 예산 집행이라 COST-01·FAP상 CEO 결정 사항이다 |

## 7. 하지 않기로 한 것

- **글 개수·분량의 수치 기준을 못 박지 않는다.** 구글이 공개하지 않는 수치라 지어내면
  근거 없는 기준이 된다. 대신 3-1(1차 자료)을 통과 조건으로 뒀다.
- **승인률을 올린다는 식의 기법을 넣지 않는다.** 검증할 방법이 없다.
- **자동 발행을 조건부로 되살리는 설계를 넣지 않는다.** 조건을 달아 두면 언젠가 켜진다.
