# 인스타그램 4컷 안전 웹툰 기준 (TOON-01)

> CEO 지시 2026-09-14 ("매일 인스타그램에 웹툰을 올릴 수 있게 할 수 있어" → "착수해").
> 게시 코드: `src/lib/instagram.ts` / 컷 이미지 프록시: `src/app/api/toon-image/route.ts`

---

## 1. 왜 이 형식인가

막히는 곳이 게시가 아니라 그림이다. 게시는 공식 API가 있어 정식 경로로 되고,
무료 이미지 생성으로 매일 웹툰을 만들 때 무너지는 건 **캐릭터 일관성**이다.
같은 인물이 매 편 다른 얼굴로 나오면 웹툰이 아니라 삽화 모음이 된다.

Higgsfield처럼 크레딧으로 일관성을 푸는 도구는 월 수입 50만원 전까지 보류다
(CLAUDE.md 금지 행동). 그래서 **일관성을 요구하지 않는 형식**을 고른다.

| 형식 | 캐릭터 일관성 요구 | 판정 |
|---|---|---|
| 스토리 웹툰(연속 서사) | 높다 | 무료 생성으로는 불가 |
| **4컷 안전 웹툰(사례 1건 = 1편)** | **낮다** | **채택** |
| 정보형 카드(도표·텍스트 중심) | 거의 없다 | 보조로만 |

4컷을 택한 이유 셋.

1. **소재가 이미 있다.** 밀폐공간·정비 중 재기동·도급 동시작업 등 네이버 블로그
   안전 글이 그대로 4컷으로 쪼개진다. CEO의 안전보건 실무 4년이 1차 자료고,
   이게 없으면 그냥 AI 그림 계정이 된다(ADSENSE-01에서 배운 것과 같은 문제).
2. **매 편이 독립 사례라 인물이 이어질 필요가 없다.** 픽토그램·실루엣 계열로
   고정하면 얼굴을 그리지 않아도 된다. 안전 교육 자료가 원래 그렇게 생겼다.
3. **크몽 위험성평가 상품과 같은 축이다.** 새 트랙을 여는 게 아니라 안전관리
   트랙의 채널이 하나 느는 것이다.

## 2. 컷 구성 (고정)

숏폼 4샷 구조(`AI_TOOLING_STANDARD.md` §9)를 그대로 가져온다. 비용 0이고
이미 채택된 구조다.

| 컷 | 목적 | 안전 웹툰에서의 대응 |
|---|---|---|
| 1 | 훅 | 평범해 보이는 현장 한 장면 |
| 2 | 전개 | 무엇이 어긋나 있는지 |
| 3 | 변화 | 그래서 무슨 일이 생기는지 |
| 4 | 마무리 | 작업 전에 정해 뒀어야 할 한 가지 |

- **4컷 고정.** 늘리지 않는다. 늘리면 대사가 길어지고 대사가 길어지면 그림이
  설명을 못 따라간다.
- **컷당 대사 2줄 이하.** 그림 안에 글자를 넣지 않는다 — 무료 생성 모델은 한글을
  제대로 못 쓴다. 대사는 캡션과 이미지 위 오버레이로 처리한다.
  오버레이는 CONDUCTOR 세션이 Canva로 얹고 1:1 JPEG로 내보낸다(CLAUDE.md CANVA-01).
- **4컷 목적을 먼저 한 줄씩 쓰고** 그다음 프롬프트를 쓴다. 순서를 뒤집으면
  그림에 이야기를 맞추게 된다.

## 3. 이미지 규격 (고정)

| 항목 | 값 | 이유 |
|---|---|---|
| 비율 | **1:1 (1024×1024)** | 캐러셀은 전 장이 첫 장 비율로 잘린다. 섞이면 잘림 사고가 난다 |
| 포맷 | **JPEG** | 인스타 게시 API가 JPEG만 받는다 |
| 스타일 | 플랫 픽토그램 / 실루엣, 색 3~4개 이내 | 인물 동일성을 요구하지 않는 유일한 축 |
| 글자 | **그림 안에 넣지 않는다** | 무료 생성 모델의 한글 렌더링이 깨진다 |
| seed | 한 편 안에서 동일 값 | 컷 사이 스타일 튐을 줄인다 |

컷 이미지는 `/api/toon-image?style=toon&prompt=<장면>&seed=<편번호>`를 거친다.
원본 URL을 인스타에 바로 넘기지 않는 이유는 두 가지다 — 포맷을 바이트로 판정해
JPEG가 아니면 조용히 넘기지 않고 막고, Meta가 가져가는 주소를 우리 도메인으로
고정한다.

**스타일 문구는 프롬프트에 쓰지 않는다.** 라우트의 `STYLE_PRESETS.toon`에 박혀
있고 `style=toon`이면 서버가 붙인다. 호출자가 매번 적으면 편마다 조금씩 달라지고,
그러면 TOON-01이 유일하게 요구하는 것(한 편 안에서 네 컷의 화풍이 같을 것)이
깨진다. **호출자는 장면만 쓴다** (장면 부분 상한 600자).

## 4. 게시 경로

**앱 심사가 필요 없다.** Advanced Access(앱 심사 + Business Verification)는
"내가 소유하지 않은 계정에 서비스할 때" 요구된다. 우리는 우리 계정 하나에만
올리므로 Standard Access로 충분하고, 계정을 앱의 Instagram Tester로 등록해
초대를 수락하면 개발 모드 그대로 발행된다.

이 판정이 중요한 이유: 사업자등록·비즈니스 인증이 **이 경로의 선행조건이
아니다.** 겸업 관련 판단과 분리해서 진행할 수 있다.

| 항목 | 값 |
|---|---|
| 방식 | 컨테이너 생성 → 상태 FINISHED 대기 → 발행 (2단계) |
| 캐러셀 | 2~10장, 24시간 한도에서 **1건**으로 계산 |
| 한도 | 24시간 이동 기준 100건 |
| 계정 | 프로페셔널(비즈니스·크리에이터) 필수 |
| 페이스북 페이지 | 2024-07 도입된 Instagram Login 경로는 **불필요** |
| 비용 | 0 |

환경변수: `IG_USER_ID`, `IG_ACCESS_TOKEN`, (선택) `IG_API_VERSION`.

## 5. 주기 — 매일이 아니라 주 2~3편으로 시작한다

블로그를 이미 매일 3건 낸다. 웹툰이 매일 붙으면 하루 4건이고, 그러면 소재보다
**검수가 먼저 무너진다.** 한 편도 CEO가 안 보고 나가는 구조가 되면 채널 전체가
자동 생성물로 읽힌다 — 애드센스 미달의 원인이었던 구조와 같다(ADSENSE-01).

- **자동 발행을 먼저 켜지 않는다.** 생성까지 자동, 발행은 CEO 확인 후.
- MULTI-01 적용: 블로그 글을 그대로 옮기지 않는다. 같은 사례를 다루더라도
  4컷은 새로 구성한다. 복사가 아니라 재구성이다.
- 주기를 올리는 건 시범 편이 쌓인 뒤 판단한다.

## 6. 금지

- 지어낸 사고 사례 금지. 겪지 않은 일을 겪은 것처럼 그리는 게 가장 큰 리스크다.
  일반적인 구조·절차를 다루되 특정 사고를 목격한 것처럼 쓰지 않는다.
- 특정 회사·현장·사람이 식별되는 묘사 금지.
- 공포 조장 이미지(실제 부상 묘사) 금지. 픽토그램 수준에서 멈춘다.
- 최상급·단정 표현 금지 (표시광고 기준, SELL-01·AEGIS 게이트와 동일).
- 법령 조문을 웹툰 안에서 단정하지 않는다. "관할 기준 확인"을 캡션에 남긴다.

## 7. 미확인

| 항목 | 상태 |
|---|---|
| Pollinations 출력 포맷이 JPEG인지 | **미확인.** 이 세션은 egress 프록시가 image.pollinations.ai를 막아(403) 직접 못 쟀다. 배포 후 `/api/toon-image?prompt=test&probe=1`을 한 번 열면 판정이 나온다 |
| `IG_API_VERSION` 기본값 v23.0 | **미검증.** graph.facebook.com도 이 세션에서 막혀 실호출을 못 했다 |
| 프로페셔널 전환의 부작용 | 기존 게시물·팔로워 영향은 사실상 없고 되돌릴 수 있는 것으로 확인. 다만 계정 공개 노출도가 올라가는 점은 CEO 판단 사항 |

## 8. 착수 순서

1. CEO — 인스타 계정을 프로페셔널로 전환
2. CEO — Meta 앱 생성, 해당 계정을 Instagram Tester로 등록·수락, 토큰 발급
3. CEO — 배포본에서 `/api/toon-image?prompt=test&probe=1` 한 번 열어 포맷 확정
4. CONDUCTOR — 시범 3편 제작(4컷 구성 + 컷별 프롬프트 + 캡션)
5. CEO — 시범 3편 확인 후 형식 확정
6. CONDUCTOR — cron 연결 (발행은 확인 후 단계 유지)
